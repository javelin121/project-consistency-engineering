# 各层 `navigation.md` 的写法

导航回答一个问题：**这一层里有哪几块，每块管什么。** 只列直接子目录，不列文件，不列孙目录。

## 长什么样

```markdown
程序源码。按模块分目录，一个模块一个文件夹；不放测试、不放数据、不放文档。

<!-- pce:map:begin -->
| 子目录 | 负责什么 | 入口 | 最后更新 |
|---|---|---|---|
| auth | 登录、会话、令牌 | auth/__init__.py | 2026-11-18 |
| billing | 计费与账单 | | 2026-11-02 |
<!-- pce:map:end -->
```

- 开头一句：这一层是干什么的、什么该放进来。没有这句，`check` 报 S4。
- 表格只有四列；`入口` 可空，`最后更新` 由 `pce map` 从 git 填，人不写。
- `<!-- pce:map:begin -->` 与 `<!-- pce:map:end -->` 之间归脚本管，外面归人管。
- 叶子目录不建这份文件。

## 两处说明必须一致

同一个目录的“负责什么”写在两个地方：父表那一行，和它自己文件的第一句。

- 分区以 `structure.yaml` 里的 `what` 为准，两处都要落在 `what` 里。
- 非分区目录没有基准，父表行与首句互为子串即通过。
- 比对前去掉标点和空格，全角半角、大小写都不算差异。

## `pce map` 会做什么

- 磁盘有、表里没有：加一行，并问“负责什么”（先看目录里有什么文件，给两三个候选）。
- 表里有、磁盘没有：删这一行，但**先问**。
- 两边都有：一个字不动；只刷新“最后更新”这一列。
- 这一层有子目录却没有 `navigation.md`：新建它，首句用 `zones.what`（分区）或问你。
- 老仓库的表没有 `<!-- pce:map:begin/end -->` 标记：转成四列再接管，前两列（子目录、负责什么）原样搬过来；多出来的列不搬，会打印提醒，原样留在 git 历史里；那层连表都没有，才新建一张空的。

非交互环境（CI、脚本、定时任务）里缺说明，它会停下、列出待补、不动任何文件。**agent 本身是交互的**，随时可以停下来问人。

## 准不准，机器判不了

脚本只保证两处一致，不保证说得对。谁读到觉得不对，当场提出来；改不改由人定，确认后 agent 落笔。

## 多分支与冲突

导航和契约都是普通文本文件，**并发交给 git**，PCE 不造锁、也不记版本向量。

- 不同分支各自改结构：合并时冲突会显式出现，这是想要的效果——不要为了避免冲突去手工协调。
- 解决冲突的顺序：先取并集（两边的行都留着）→ 跑 `pce map`（磁盘上有的补行、没有的删行、时间列重算）→ 跑 `pce check`（看“负责什么”是否还与 `structure.yaml` 一致）。
- 不要逐行手抄表格：`map` 只动行和“最后更新”，人写的单元格它不碰，所以“并集 + map”比手工对齐稳。
- `structure.yaml` 冲突按语义合并，判据是合并后能通过 `pce check`；两边都改了同一个分区时，以人确认的那份为准。
- 同一个工作树里同时有两个 agent 改结构，git 管不了，也不在保护范围：串行执行。
