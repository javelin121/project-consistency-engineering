# 第一次进一个仓库，按这个顺序看

不要一上来就翻代码。先回答四个问题：它是什么、东西在哪、谁管哪块、现在有没有病。

## 顺序

1. **有没有 `structure.yaml`**
   - 有：读它。这是唯一的判定依据，先看 `zones` 和 `root.allow`。
   - 没有：这是老仓库或新仓库。跑 `pce audit` 拿现状，别急着改。

2. **根目录有什么**
   一眼扫过去：散件（`notes.txt`、`tmp/`、`.DS_Store`）、工具目录（`.` 开头）、入口文件（`README.md`、`AGENTS.md`）。

3. **导航**
   根 `navigation.md` 有没有、每层有没有、表里的“负责什么”是空话还是人话。这一眼决定 I2 现在成不成立。

4. **`AGENTS.md`**
   行数、有没有日志和日期。超过 120 行或满是日期的，先记一笔，别当场改。

5. **跑一遍检查**
   `pce check`。先看 error 数量，再看 warn 分布。

## 必须问用户的三件事

- 这块目录到底归谁管：`what` 一句话，只有人能给。
- 老仓库里哪些是历史包袱、哪些还在用：决定进不进归档区。
- 改结构的边界：能不能动文件、能不能改引用、有没有不能碰的目录。

## 别做的事

- 别猜目录用途。猜错了整套导航就是假的。
- 别一上来就 `git mv`。老仓库先出报告，人点头再动。
- 别把 `audit` 的“坏味道”当结论。它只报现象，判断归人。
