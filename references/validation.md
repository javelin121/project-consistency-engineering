# 12 条检查

`pce check` 全部跑完再汇总，一次只读一遍磁盘。默认查全仓，`--paths` 只查指定路径。

| 编号 | 查什么 | 底线 | 级别 |
|---|---|---|---|
| S1 | 根目录合规：根下文件都在 `root.allow`；根下目录是分区、归档区、`ignore` 里，或以 `.` 开头（工具目录在任何层级都不要求导航、不占父表、不查命名，但内容仍受引用检查） | I1 | error |
| S2 | 每个有子目录的目录都有 `navigation.md` | I2 | error |
| S3 | 双向对账：子目录在父表有行且“负责什么”非空；父表每行都对应真实目录（过期行也算 error） | I2 | error |
| S4 | 目录说明一致：分区以 `what` 为准，父表行与首句都要落在 `what` 里；非分区互为子串即可 | I2 | warn |
| S5 | 文档链接失效 → error；代码里带路径的字符串失效 → warn | I4 | error / warn |
| S6 | 归档区里的文件，别处还按旧路径引用它 | I4 | error |
| S7 | 父表列了子目录，但整棵子树里一个非归档文件都没有 | I2 | warn |
| S8 | 两个分区的职责重叠（`what` 高度相似，或名字互为父/子串） | I1 | warn |
| S9 | “负责什么”写成了空话（其他、杂项、临时、暂存、待定） | I2 | warn |
| S10 | 归档区每个文件在 `ARCHIVE.md` 有登记（`ARCHIVE.md` 自己除外） | I4 | warn |
| S11 | `AGENTS.md` 超 120 行、不同日期达到 10 个；PCE 段重复/未闭合；段落后于当前模板，或段被改过没有可信版本记录 | I5 | warn |
| S12 | 仓库里还留着 PCE 脚本的副本（除了你自己 vendored 的那一份；按文件头特征认，不认文件名） | I4 | warn |

## 豁免

- `ignore` 里的目录整棵子树不参与，S2、S3、S8 和 `map` 也跳过。
- 任何层级上以 `.` 开头的工具目录（`.github/`、`.vscode/`）：S2、S3、S4、S8、S9 和 `map` 都跳过它；但里面的文件仍然参与 S6、S7。
- 归档区内部不要求 `navigation.md`、不查命名与归属；只受 S7、S11 管。
- 同一处问题只报一次：归档后旧路径同时触发 S5 和 S6 时，只报 S6。
- S6 不拆成“文档链接”和“代码路径”两条：一条规则里已经用 `error` / `warn` 分开了两级，拆开只会让编号变多、判断变碎。
- PCE 自己的脚本不参与 S5 和 `explain` 的引用扫描：里面是示例路径，不是真引用。按内容特征认（文件头含 `pce — project consistency engineering`，或同时含 `CONTRACT = "structure.yaml"` 与 `VERSION = "`），改文件名躲不掉。

## 输出

每条一行四样：**位置、底线、级别、一句说明**。error 在前，同级按路径排，末尾一行汇总。

说明要具体到能照着改；没有通用改法的（比如说明写得对不对），写“要人判断”。

退出码：`0` 没有 error；`1` 有 error（`--strict` 时只有 warn 也算 1；info 不算失败）；`2` 用法错误。

## warn 由 agent 复核

脚本只负责把可疑的地方挑出来。是不是真问题、怎么改，人和 agent 判断。

## 强制层级要说实话

| 手段 | 强度 | 实话 |
|---|---|---|
| 本地命令 | 弱 | 只有主动跑才起作用 |
| 提交钩子 | 中 | 装了才有；可以 `--no-verify` 绕过 |
| CI | 较强 | 还得配分支保护，否则红着也能合 |
| 分支保护 | 最强 | 要仓库管理员权限 |

“有配置”不等于“跑过”，更不等于“被要求”。别把话说过头。
