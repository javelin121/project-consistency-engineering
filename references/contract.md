# `structure.yaml`：这份契约怎么写

它放在仓库根目录，是这套规则唯一的事实源。`AGENTS.md`、`navigation.md` 都是它的投影；手改导航不影响判定，`check` 只认它。

## 六个字段

```yaml
version: 1

zones:
  src:
    what: 程序源码
  tests:
    what: 测试

root:
  allow:
    - README.md
    - pyproject.toml

naming:
  default: snake
  zones:
    docs: kebab

archive:
  path: archive/

ignore:
  - .venv/
  - dist/
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 目前只有 `1`；不认的值直接报错 |
| `zones` | 是 | 分区表，键是目录名，值含 `what`（必填） |
| `root.allow` | 否 | 追加到内建 41 项之后，用于放行这个项目特有的根文件 |
| `naming` | 否 | `default` 全局风格，`zones` 按分区覆盖，`files` 按文件名模式覆盖 |
| `archive.path` | 否 | 归档区位置，默认 `archive/`；写空字符串表示没有归档区 |
| `ignore` | 否 | 整棵子树不参与检查，`pce new` 也拒绝往里建 |

## 分区是什么

分区 = 仓库顶层按职责切出的一块。名字只能是根目录下的一级目录名，不能是多层路径。

`what` 是给人和 agent 看的一句话：这一块装什么。它是判断“这个文件放这儿说不说得通”的唯一依据，所以别写“其他”“杂项”“暂存”。

分区不规定文件类型。代码目录里出现 `.md`、`.json`、`.sql` 是正常的；这个 skill 只管归属，不管格式。

## 命名（只是建议）

| 风格 | 样子 | 适合 |
|---|---|---|
| `snake` | `user_profile.py` | Python |
| `kebab` | `user-profile.md` | 文档、目录 |
| `pascal` | `UserProfile.tsx` | React 组件 |
| `camel` | `userProfile.ts` | 部分 JS/TS |

只写风格名，不写正则。命名**不进检查**：风格由业务场景决定，`pce` 只在 `new` 和 `explain` 里给建议，不拦人。不写 `naming` 或对应分区没写，就不给建议。

## 格式限制

只支持 YAML 的一个子集：注释、`键: 值`、两格缩进嵌套、`- ` 列表、行内列表、字符串、布尔、整数。

不支持锚点、块标量（`|`、`>`）、行内映射、多文档。解析器只认这一个文件，写错了会报“第几行”。

## 默认值

内建 41 项（常见单文件配置、锁文件、入口文件）永远生效；你写的 `root.allow` 是**追加**，不是替换。`init` 会扫一遍根目录，把内建清单里没有的文件写进 `root.allow`。

`ignore` 内建 `.git/`、`.venv/`、`node_modules/`，这三类直接拒绝，不给选项。

## 判定用的阈值与词表

这几处是脚本内部常量，改它们等于改判定口径，所以写在这里对账：

| 用在哪 | 判据 | 值 |
|---|---|---|
| `pce new` 查重（名字） | 忽略大小写后：完全相同、互为前缀、去掉尾部复数相同、去掉 `-`/`_` 后相同、`difflib` 相似度 | `≥ 0.8` |
| `pce new` 查重（说明） | 去停用词后两边词集的 Jaccard 系数 | `≥ 0.6` |
| S9 空话 | “负责什么”只写了这些词之一 | 其他、杂项、临时、暂存、待定 |

新建**分区**比新建普通子目录更严：说明相似时不提供“确实要单独建”这个默认选项。

## 没有 git 的时候

`check` 不依赖 git，照常跑。受影响的是两处：

- `map` 的“最后更新”列取 `git log -1 --format=%cs -- <路径>`；没有 git 就取不到，这一列留空，**不退回文件修改时间**（mtime 会被 checkout、拷贝改掉，比空着更容易误导）。
- `archive` 的 `git mv` 会失败，退化成普通移动，历史不再连续——这一步会明说，不假装成功。

## `map` 要么全写，要么全不写

`map` 分两阶段：先把每一层的新表格算出来放在内存里，全部算完才统一落盘。中间任何一层缺“负责什么”、或者需要新建导航而没人回答，整个命令退出 1，一个文件都不写，并列出“这次也不改”的那些层。

`--strict` 之外的退出码只有三个：`0` 成功；`1` 失败（检查不通过、前提不满足、用户中止）；`2` 用法错（参数不对、路径不存在、不在仓库根）。

## 生成记录

`structure.yaml` 的第一行是注释 `# generated by pce <版本>`，写的是建这个仓库时的 skill 版本，不参与解析、不影响校验。它的用处只有一个：让 `check` 能说“这个仓库按 0.2.0 建的，当前 0.5.0”，让 `upgrade-repo` 知道要不要迁移。手改它没有意义，`upgrade-repo` 会补上。
